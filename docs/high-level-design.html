Executive Summary

ResearchHub helps a research team turn an early idea into shared notes, tasks, saved sources, discussion, and a carefully controlled public project page. It is not a code-hosting system; code and datasets remain in GitHub or other dedicated repositories.

Private workspaces

Role-protected projects for notes, tasks, messages, and sources.

Useful AI

One transparent source-analysis workflow with clear job status and safe failure handling.

Public discovery

Opt-in public project cards, filtering, bookmarks, and collaboration requests.

Scope and Success Criteria

In scope for the MVP

  • Authentication, profiles, and private projects.
  • Members with Owner, Editor, and Viewer roles.
  • Notes, tasks, messages, and saved sources.
  • Realtime updates for chat and task changes.
  • One AI source-analysis workflow.
  • Controlled public discovery and join requests.

Deliberately out of scope

  • Google Docs-style simultaneous rich-text editing.
  • Custom model training or autonomous agents.
  • Microservices, Kubernetes, and premature scaling.
  • Recommendation systems before public search works.

Definition of done: authenticated users can collaborate safely in a private project, use one reliable AI analysis tool, and discover or request access to public projects.

Design Principles

Server is authoritative

The UI improves usability but never grants access. FastAPI and database policies enforce permissions.

Database is the record

PostgreSQL is the source of truth. Realtime signals changes but does not replace canonical data.

Start simple

Use a modular monolith first. Add a queue and worker only when synchronous AI analysis is proven.

System Architecture

The MVP is a modular monolith: one web application, one trusted API, and one PostgreSQL database. AI background processing is introduced after the first synchronous workflow proves its value.

Key Request Flows

Create a project

sequenceDiagram
  participant B as Browser
  participant A as FastAPI
  participant D as PostgreSQL
  B->>A: POST /projects (title, summary, field)
  A->>A: Validate input and authenticate user
  A->>D: Insert project and owner membership
  D-->>A: Created project
  A-->>B: 201 Created + project JSON

Run AI source analysis

sequenceDiagram
  participant B as Browser
  participant A as FastAPI
  participant D as PostgreSQL
  participant Q as Queue
  participant W as AI worker
  participant L as Model provider
  B->>A: POST /ai/jobs
  A->>A: Verify project membership
  A->>D: Create ai_jobs row (queued)
  A->>Q: Enqueue job id
  A-->>B: 202 Accepted + job id
  Q->>W: Deliver job id
  W->>L: Analyze permitted source text
  L-->>W: Structured analysis
  W->>D: Save result (complete or failed)
  D-->>B: Realtime status update

The AI worker prevents a slow or failing model provider from blocking the user-facing API. Retries are limited and failures return safe messages without inventing results.

API Design

Use versioned, resource-oriented HTTP endpoints. Every project-scoped route authenticates the caller and verifies membership before reading or changing data.

MethodEndpointPurposeExpected status
POST/projectsCreate a project and owner membership.201
GET / PATCH/projects/{id}Read or update project details.200
POST/projects/{id}/membersInvite or add a collaborator.201
GET / POST/projects/{id}/tasksList or create tasks.200 / 201
GET / POST/projects/{id}/notesList or create notes.200 / 201
GET / POST/projects/{id}/messagesRead or send chat messages.200 / 201
POST / GET/ai/jobs / /ai/jobs/{id}Queue and inspect an AI task.202 / 200
GET/exploreFilter and search public projects only.200

Response conventions

  • 200 successful read or update
  • 201 resource created
  • 202 background job accepted
  • 401 unauthenticated
  • 403 authenticated but not permitted
  • 404 resource unavailable or hidden by access policy
  • 422 invalid request data

Security, Authorization, and Privacy

Role model

Owner: settings, publishing, membership, deletion. Editor: notes, tasks, messages, sources. Viewer: read-only access.

Defence in depth

FastAPI performs role checks; Supabase Row Level Security repeats the same rule at the database boundary.

AI privacy

Never expose or persist provider keys. Show users when content leaves the product for cloud analysis; support local Ollama later.

flowchart TD
  R[API request] --> I{Authenticated?}
  I -- No --> U[401 Unauthorized]
  I -- Yes --> M{Project member?}
  M -- No --> F[403 Forbidden or 404]
  M -- Yes --> O{Role permits action?}
  O -- No --> F
  O -- Yes --> D[Database action protected by RLS]
  • Do not trust hidden buttons, client-side route guards, or a browser-supplied user id.
  • Keep private database credentials and AI secrets only in backend or worker environment variables.
  • Do not log source text, passwords, tokens, or API keys by default.
  • Embed and search only content explicitly published as public.

Quality Strategy

Testing pyramid

  • Unit: Pydantic models and business rules.
  • Integration: FastAPI endpoints, authorization, database queries.
  • End-to-end: sign in → project → task → AI-job happy path.

Acceptance checks

  • Unauthenticated visitors cannot access the dashboard.
  • Private projects cannot be opened by changing a URL.
  • Viewer write attempts return 403.
  • Realtime changes converge with canonical database state after reload.
  • Failed AI calls never create fabricated analysis.

Use linting, type checks, API tests, and accessibility checks in continuous integration. Keep test fixtures synthetic; never use unpublished research material in demos.

Risks and Architectural Decisions

Risk or decisionApproachReason
Private-project leakageAPI membership checks plus Supabase RLS.Browser UI alone cannot protect data.
Simultaneous updatesLast-write-wins with timestamps and history; add optimistic locking later.Simple and defensible before CRDT complexity.
Duplicate AI jobsDisable while queued and use an idempotency key.Prevents cost and confusing duplicate output.
Worker/provider failureBounded retries, safe errors, explicit job states.Reliability without pretending a failed analysis succeeded.
Architecture sprawlModular monolith first, queue only when needed.Finishing a reliable system is more valuable than premature microservices.
